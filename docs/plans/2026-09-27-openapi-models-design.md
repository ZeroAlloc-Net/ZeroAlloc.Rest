# OpenAPI model generation and AOT-safe serialization: design

- **Issue:** ZeroAlloc-Net/ZeroAlloc.Rest#351
- **Status:** approved design, 2026-09-27
- **Release:** breaking, ships in **Rest 3.0.0**

## 1. Problem

The OpenAPI codegen (the `zeroalloc` CLI and `ZeroAlloc.Rest.Tools.MSBuild`) generates only a client interface:

- A `$ref` schema becomes a bare type name (`Task<User>`) whose type is never generated, so any real spec's output does not compile until every DTO is written by hand.
- Request bodies are always `[Body] object body`.
- Parameter types ignore `format`, enums and nullability. `int64` becomes `int`, and `uuid` and `date-time` become `string`.

The AOT story beneath it is also incomplete:

- `SystemTextJsonSerializer` only takes `JsonSerializerOptions` and stays `[RequiresDynamicCode]`.
- The Native AOT cookbook declares a `[JsonSerializable]` context that is never used.
- The ZeroAlloc.Serialisation README's Rest snippet calls a constructor that does not exist.

## 2. Goals and non-goals

**Goals**
- Generate models for every schema the interface references.
- Type request bodies and parameters from their schemas.
- Emit an STJ source-gen context covering every generated type.
- Give `Rest.SystemTextJson` an AOT-safe, context-based constructor.
- Generated methods return `Task<Result<T, HttpError>>`, so a non-2xx status, a transport failure, a timeout and a deserialization failure all come back as error results, not exceptions.

**Non-goals, each a separate issue**
- OpenAPI 3.1 and the Microsoft.OpenApi 2.x upgrade.
- XML, multipart and form bodies, which keep today's behaviour.
- A ZeroAlloc.Serialisation multi-type adapter. Its STJ backend wraps the same `JsonTypeInfo<T>`, so it adds no speed for JSON. Add it later only if someone asks.

## 3. Decisions

| Topic | Decision |
|---|---|
| Model shape | `public sealed record` with `required` and `init` properties |
| Output | One spec produces one `.cs` file and one namespace. Order: interface, models, JSON context. `// <auto-generated/>` header. Existing `--output`/`OutputPath` unchanged. |
| Serialization | Generated `{Interface}JsonContext : JsonSerializerContext`, plus new `SystemTextJsonSerializer` constructors that take a context or resolver |
| Return type | Always `Task<Result<T, HttpError>>`, or `Task<UnitResult<HttpError>>` for operations with no response body. There is no `Task<T>` mode. `UnitResult<E>` exists in ZeroAlloc.Results, but the Rest source generator doesn't support it yet, so this design adds that support (§6). |
| Enums | Strict. An unknown value throws `JsonException`, which the client maps to `HttpError { Kind = Deserialization }`. |
| Composition | Full: allOf flattened, discriminated oneOf/anyOf as STJ polymorphism, undiscriminated oneOf/anyOf as generated union wrappers |
| Models | On by default. `--models false` / `GenerateModels="false"` keeps hand-written DTOs. |
| Compatibility | Breaking, so `feat!` and Rest 3.0.0 |

## 4. Architecture

All tool code lives in the shared project `ZeroAlloc.Rest.Tools.Shared`, which is compiled into both the CLI and the MSBuild task. The single `OpenApiInterfaceGenerator` is split into units that each have one job:

| Unit | Responsibility | Output |
|---|---|---|
| `SchemaModelBuilder` | Reads `components/schemas` and inline schemas into an intermediate model: `RecordModel`, `EnumModel`, `PolymorphicModel` and `UnionModel`. Owns naming, collision handling and composition resolution. | Intermediate model only, with no strings, so it can be unit-tested on its own |
| `TypeMapper` | Maps a schema to a C# type reference (§5.1) | `TypeRef` |
| `ModelEmitter` | Writes records, enums, polymorphic hierarchies, union wrappers and union converters | C# source |
| `JsonContextEmitter` | Writes the `JsonSerializerContext` with `[JsonSerializable]` for every model, plus every method's request and response type, including `List<T>` and `Dictionary<string,T>` shapes | C# source |
| `OpenApiInterfaceGenerator` | Writes the interface using `TypeMapper` for parameters, bodies and returns, and assembles the file | The file |

The intermediate model is plain and value-equal. The emitters are pure functions of it.

## 5. Type rules

### 5.1 Primitive and format mapping

| Schema | C# |
|---|---|
| `integer`, or with `format: int32` | `int` |
| `integer` with `format: int64` | `long` |
| `number` | `double` |
| `number` with `format: float` | `float` |
| `number` with `format: decimal` | `decimal` |
| `string` | `string` |
| `string` with `format: date-time` | `DateTimeOffset` |
| `string` with `format: date` | `DateOnly` |
| `string` with `format: time` | `TimeOnly` |
| `string` with `format: uuid` | `Guid` |
| `string` with `format: uri` | `Uri` |
| `string` with `format: byte` | `byte[]` (base64) |
| `string` with `format: binary` | `Stream`, request and response bodies only |
| `boolean` | `bool` |
| `array` | `List<T>` |
| `object` with `additionalProperties` only | `Dictionary<string, T>` |
| `$ref` | the generated type |

Parameters (path, query and header) use the same mapper. Headers stay `string` unless their schema says otherwise.

### 5.2 Records

- Each object schema becomes one `public sealed record`.
- **Required property:** `public required T Name { get; init; }`.
- **Optional property:** `public T? Name { get; init; }`.
- **Required and `nullable: true`:** `public required T? Name { get; init; }`.
- **Wire names:** every property carries `[JsonPropertyName("wire")]`. Identifiers are PascalCased and sanitised with the existing identifier rules: invalid characters removed, keywords escaped with `@`, collisions given a numeric suffix.
- **Inline object schemas** are named from their path, for example `User` + `address` gives `UserAddress`.
- **`readOnly` and `writeOnly`** are documentation only and are ignored.
- **Descriptions** become `/// <summary>` doc comments, XML-escaped.

### 5.3 Enums (strict)

- A string enum becomes a C# `enum`. Each member carries `[JsonStringEnumMemberName("wire")]`, and the type carries `[JsonConverter(typeof(JsonStringEnumConverter<T>))]`, which is AOT-safe.
- **Integer enums:** members are named `Value<n>`, or taken from `x-enum-varnames` when present.
- **Unknown values:** no `Unknown` member is generated. An unknown value throws `JsonException`, and the generated client already maps deserialization exceptions to `HttpErrorKind.Deserialization`. See `ClientEmitter.cs`, around the deserialize guard.

### 5.4 allOf

The parts are flattened into one record:

- the properties are the union of the parts' properties;
- a property is required if any part requires it;
- the same property with conflicting types is a **generation error**, raised with a clear message that names the schema and the property.

### 5.5 oneOf and anyOf with a discriminator

- The base becomes `public abstract record Base` with `[JsonPolymorphic(TypeDiscriminatorPropertyName = "<propertyName>")]`, plus one `[JsonDerivedType(typeof(Variant), "<value>")]` for each variant.
- Each variant becomes `public sealed record Variant : Base`.
- Values come from `discriminator.mapping` when present, and otherwise from the schema name.

### 5.6 oneOf and anyOf without a discriminator: union wrappers

**Generated shape:**

```csharp
[JsonConverter(typeof(PetOrErrorConverter))]
public sealed record PetOrError
{
    public Pet? AsPet { get; init; }
    public Error? AsError { get; init; }
    public TResult Match<TResult>(Func<Pet, TResult> pet, Func<Error, TResult> error);
    public void Switch(Action<Pet> pet, Action<Error> error);
}
internal sealed class PetOrErrorConverter : JsonConverter<PetOrError> { … }
```

**How the converter reads a value:**

1. Parse the value once into a `JsonDocument`.
2. **Filter by JSON kind:** object, array, string, number or bool.
3. **Filter object candidates** to those whose required properties are all present.
4. **Pick the best match:** the most matched required properties wins. Declaration order breaks any remaining tie.
5. **Apply the oneOf/anyOf rule:** for `oneOf`, more than one candidate after step 3 is **ambiguous** and throws `JsonException`; for `anyOf`, the step 4 winner is used.
6. **Deserialize** the chosen variant through the generated context's `JsonTypeInfo<T>`, with no reflection.

**Writing:** the converter serializes whichever variant is set. None set, or more than one set, throws `JsonException`.

**Validity rules:**
- The tool emits the converter as **source**, not from a generator, so STJ source-gen sees the `[JsonConverter]` attribute. The cross-generator blind spot does not apply.
- Unions of primitives are supported the same way; the JSON kind decides.

### 5.7 Unsupported shapes

These map to `JsonElement` and raise a new warning, **ZRT002** "schema mapped to JsonElement", with the schema path and the reason:
- `not`;
- recursive `allOf`;
- schemas with neither a type nor composition.

It can be suppressed with `--nowarn ZRT002` or `NoWarn` on the item.

## 6. Interface changes

- **Bodies:** `[Body] <MappedType> body` instead of `object`.
- **Returns:** `Task<Result<T, HttpError>>` for every operation. The success type comes from the first 2xx response with a schema. An operation with no 2xx schema returns `Task<UnitResult<HttpError>>`.
- **Generator change:** the Rest source generator (`ModelExtractor` and `ClientEmitter`) learns `UnitResult<HttpError>` returns, and `UnitResult<TError>` with an `[ErrorMapper]`. Failures map exactly as for `Result<T, E>`. On success the body is not read, and the method returns `UnitResult<E>.Success()`. This comes with its own generator tests and docs in `docs/advanced.md`.
- **Result semantics are unchanged,** per `docs/advanced.md` "What still throws". A non-2xx status, a transport failure, a timeout and a deserialization failure become an `HttpError`. Caller-requested cancellation and a request body that can't be serialized still throw. The migration guide says so.
- **Parameters:** mapped through `TypeMapper` (§5.1).
- **Types:** the `Result` and `HttpError` types come from ZeroAlloc.Rest and ZeroAlloc.Results, via the same usings the generator already relies on.

## 7. Runtime: `ZeroAlloc.Rest.SystemTextJson`

**New constructors, additive:**
- `SystemTextJsonSerializer(JsonSerializerContext context)`
- `SystemTextJsonSerializer(IJsonTypeInfoResolver resolver, JsonSerializerOptions? options = null)`

**Behaviour:** resolve `JsonTypeInfo<T>` through the resolver for both serialize and deserialize. A type that isn't registered throws `InvalidOperationException`, naming `T` and pointing to the generated context. There is never a fallback to reflection.

**AOT annotations:** `IRestSerializer`'s methods carry `[RequiresDynamicCode]` and `[RequiresUnreferencedCode]`.

- **First step:** prototype whether the resolver path can be called with no trim or AOT warnings at the generated call sites. Measure it with `PublishAot` on the smoke app.
- **If the warnings can't be removed that way:** introduce an annotation-free interface, for example `ITypeInfoRestSerializer`, with `JsonTypeInfo`-based or resolver-based methods. The generated client prefers it when the registered serializer implements it.
- **Never** use a suppression. Since 3.0 is a major, changing or removing the annotations on `IRestSerializer` itself is also allowed if that proves cleanest; record the choice in the plan.

**Usage:**

```csharp
services.AddIPetStoreClient(o =>
    o.UseSerializer(new SystemTextJsonSerializer(PetStoreClientJsonContext.Default)));
```

**Docs to fix:**
- `docs/cookbook/04-native-aot-publish.md`: actually use the context.
- `docs/native-aot.md`.
- `docs/serialization.md`: the new constructors.
- The ZeroAlloc.Serialisation README's Rest snippet, which has a wrong constructor. This is a separate PR in that repo.

## 8. Tool options

| CLI | MSBuild item metadata | Default |
|---|---|---|
| `--models true\|false` | `GenerateModels` | `true` |
| `--nowarn` (existing) | `NoWarn` (existing) | none |

There is no return-style option: Result only.

## 9. Compatibility and release

- **Rest 3.0.0**, `feat!` with a `BREAKING CHANGE` footer. Regenerating changes three things:
  - return types become `Result`;
  - bodies are typed;
  - models are generated, so they may clash with hand-written DTOs. `--models false` avoids that.
- **Migration guide:** add `docs/migrating-to-v3.md`.
- **Release sequencing:** release the held **Rest 2.2.0** (#328) first, so its non-breaking fixes reach users without the major.
- **One 3.0, everything in:** before 3.0 ships, sweep Rest for `[Obsolete]` members and other breaking candidates and bundle them, including Rest#336, the DI-free slimming.

## 10. Testing

1. **Unit tests:** `TypeMapper` gets one test per row of §5.1, plus nullability. `SchemaModelBuilder` gets tests for naming, inline schemas, collisions, allOf merge and conflicts, discriminator mapping, and union building.
2. **Compile tests:** following the `OpenApiRouteBindingTests` pattern, every fixture spec is generated, then compiled with the Rest source generator and analyzers against real references. It must produce **0 diagnostics**.
3. **Round-trip tests** through the generated context:
   - records, including required and nullable combinations;
   - enums, including an unknown value;
   - an end-to-end `HttpErrorKind.Deserialization` result through a generated client with a stub handler;
   - polymorphism;
   - unions, including ambiguity for oneOf versus anyOf and every JSON kind.
4. **Real-world specs:** Petstore, plus a composition-heavy public subset of GitHub or Stripe. The output must compile with 0 diagnostics.
5. **AOT smoke:** a sample client using the generated context, published with `PublishAot`, with **0 trim or AOT warnings** and a real request against a stub server.
6. **Serializer tests:** the new constructors, plus the not-registered error message.

## 11. Risks

- **Union matching is heuristic.** It is made deterministic, documented and tested. For oneOf, ambiguity is an error, never a guess.
- **Large specs make large files.** Acceptable for generated code; the output is written only when its content changes (already true).
- **`JsonStringEnumMemberName`** requires .NET 9 or later. Rest targets net10.0, which is fine.
